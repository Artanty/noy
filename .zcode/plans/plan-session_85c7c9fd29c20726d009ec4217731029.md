Let POST /thru carry its parameters as a JSON request body instead of query-string only.

## Changes

1. **`feat/back/features/thru/v1/py/thru.py`** (source of truth), then vendor byte-identical to `noy/back/thru.py`:
   - In the route handler, when the request is a POST with a JSON body, read `target`, `method`, `body`, `headers`, `timeout_s` from the JSON object. Values given as query params win over body values (query stays backward-compatible; mixing works predictably).
   - `body` may be a JSON object (forwarded as-is, serialized with `json.dumps`) or a string (forwarded verbatim, as today).
   - `headers` follows the same rules as the v1.1 query param (JSON object, hop-by-hop headers dropped, non-object → 400).
   - Non-object JSON body → 400 with a clear error.
2. **`feat/back/docs/thru.md`**: document POST-with-JSON-body form in the param table + a v1.2 version note.
3. **`feat/back/test/test_thru_py.py`**: add contract tests — POST with JSON body (target/method/body/headers all from body), query-overrides-body precedence, string body passthrough, 400 on non-object body.
